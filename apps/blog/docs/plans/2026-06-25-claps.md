## T-04: Criar `src/lib/claps.ts` — **revisado: cliente HTTP, não mais Postgres direto**

**Tipo:** feature
**Agente:** backend

Em vez de helpers sobre Postgres, `src/lib/claps.ts` passa a ser um cliente HTTP fino de `apps/api`:

```ts
const API_URL = import.meta.env.CLAPS_API_URL;
const API_SECRET = import.meta.env.CLAPS_API_SECRET;

export async function getClaps(slug: string, uid: string | undefined) {
  const res = await fetch(`${API_URL}/claps/${slug}?uid=${uid ?? ''}`, {
    headers: { 'X-Internal-Secret': API_SECRET },
  });
  if (!res.ok) throw new Error(`claps api ${res.status}`);
  return res.json() as Promise<{ total: number; userClaps: number }>;
}

export async function incrementClaps(slug: string, uid: string, amount: number) {
  const res = await fetch(`${API_URL}/claps/${slug}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'X-Internal-Secret': API_SECRET },
    body: JSON.stringify({ uid, amount }),
  });
  if (!res.ok) throw new Error(`claps api ${res.status}`);
  return res.json() as Promise<{ total: number; userClaps: number }>;
}
```

A lógica de cap (50/usuário) e upsert atômico continua existindo — só que agora roda dentro de `apps/api` (T-03 de `docs/plans/2026-06-25-api-claps-backend.md`), não aqui.

**Critérios de aceite:**
- [ ] `getClaps`/`incrementClaps` propagam erro claro (não silencioso) se `apps/api` responder não-2xx.
- [ ] Nenhuma referência a `postgres`/`ioredis` sobra em `apps/blog` depois desta tarefa.

## Riscos de implementação

> Riscos de Postgres/Redis expostos e de pool de conexões serverless não se aplicam mais a este plano (resolvidos pela arquitetura de `apps/api`) — ver riscos atuais em `docs/plans/2026-06-25-api-claps-backend.md`.

| Risco | Mitigação |
|---|---|
| `@astrojs/vercel` incompatível com versão atual do Astro 5 | Checar changelog/compat antes de instalar; testar build local primeiro |
| Condição de corrida no cap de 50 claps (cliques simultâneos de abas) | Resolvido no lado de `apps/api` (upsert atômico via Prisma/Postgres) — o blog não precisa se preocupar com isso |
| Rota dinâmica passa a depender de `apps/api` estar acessível em runtime | Falha de `apps/api` (erro de rede, 5xx) deve retornar erro claro ao client, não quebrar o resto do site (rota isolada) |
| Cookie bloqueado (navegador/extensão de privacidade) | Sem `uid`, `GET` retorna `userClaps: 0`; `POST` ainda funciona criando um uid novo na resposta |
