## TASK-01 — Criar hook `useWakeLock`

**Tipo:** feature  
**Agente:** frontend  
**Arquivo:** `apps/metronome/src/hooks/use-wake-lock.ts` *(novo)*

### O que fazer

Criar hook com assinatura:

```typescript
export function useWakeLock(isActive: boolean): void
```

**Lógica interna:**

```typescript
import { useEffect, useRef } from 'react';

export function useWakeLock(isActive: boolean): void {
  const sentinelRef = useRef<WakeLockSentinel | null>(null);
  const isAcquiringRef = useRef(false);

  useEffect(() => {
    if (!('wakeLock' in navigator)) return;

    const acquire = async () => {
      if (isAcquiringRef.current) return;
      if (sentinelRef.current && !sentinelRef.current.released) return;

      isAcquiringRef.current = true;
      try {
        const sentinel = await navigator.wakeLock.request('screen');
        sentinelRef.current = sentinel;
        // sentinel 'release' evento: limpa a ref quando o SO libera proativamente
        sentinel.addEventListener('release', () => {
          if (sentinelRef.current === sentinel) {
            sentinelRef.current = null;
          }
        });
      } catch (err) {
        console.warn('[useWakeLock] acquire failed:', err);
      } finally {
        isAcquiringRef.current = false;
      }
    };

    const release = async () => {
      const s = sentinelRef.current;
      if (s && !s.released) {
        sentinelRef.current = null;
        await s.release().catch(() => {});
      }
    };

    const handleVisibilityChange = () => {
      if (document.visibilityState === 'visible' && isActive) {
        acquire();
      }
    };

    if (isActive) {
      acquire();
    } else {
      release();
    }

    document.addEventListener('visibilitychange', handleVisibilityChange);

    return () => {
      document.removeEventListener('visibilitychange', handleVisibilityChange);
      // cleanup libera sentinel — React Strict Mode chama isso antes da remontagem
      release();
    };
  }, [isActive]);
}
```

**Notas de design:**

- `isAcquiringRef` serializa chamadas assíncronas concorrentes (toggle rápido).
- O guard `sentinelRef.current && !sentinelRef.current.released` evita dupla aquisição.
- O cleanup captura `sentinelRef` via ref (mutable), não closure — correto no Strict Mode.
- O listener `'release'` no sentinel é adicionado no objeto local `sentinel`, não precisa ser removido no cleanup do efeito porque o objeto é descartado junto com o release.
- `release()` no cleanup usa `s.released` para não chamar `release()` em sentinel já liberado.

### Critérios de Aceite

- [ ] `isActive = true` → sentinel adquirido; `isActive = false` → sentinel liberado.
- [ ] Toggle rápido (true → false → true em < 100ms) não cria dois sentinels ativos.
- [ ] Troca de aba + retorno com `isActive = true` → sentinel readquirido.
- [ ] Navegador sem `navigator.wakeLock`: nenhum erro lançado, nenhum warn.
- [ ] Bateria em economia: erro capturado em `console.warn`, nenhuma exceção propagada.
- [ ] React Strict Mode: sem sentinel órfão após ciclo mount→cleanup→mount.

## TASK-02 — Integrar `useWakeLock` em `useMetronome`

**Tipo:** feature  
**Agente:** frontend  
**Arquivo:** `apps/metronome/src/hooks/use-metronome.ts` *(modificar)*

### O que fazer

Adicionar chamada ao hook dentro de `useMetronome`, passando `isPlaying`:

```typescript
// apps/metronome/src/hooks/use-metronome.ts

import { useWakeLock } from './use-wake-lock';   // ← adicionar import

export function useMetronome(): MetronomeState & MetronomeActions {
  // ... estado e refs existentes ...

  useWakeLock(isPlaying);   // ← adicionar após os useState/useRef, antes dos useEffect

  // ... restante do hook inalterado ...
}
```

Nenhuma alteração em `MetronomeState`, `MetronomeActions` ou na interface pública do hook.

### Critérios de Aceite

- [ ] `MetronomeState` e `MetronomeActions` permanecem idênticos (sem breaking change).
- [ ] Ao clicar em Play, Wake Lock é solicitado.
- [ ] Ao clicar em Stop ou timer expirar, Wake Lock é liberado.
- [ ] Nenhum warning de lint ou erro de tipo introduzido.
